# Матрица проверки пользовательского интерфейса

Документ фиксирует сценарии ручной стабилизации Web UI. Проверки выполняются в браузере на локальном экземпляре; отсутствие статической ошибки в исходнике само по себе не доказывает успешный runtime-сценарий.

## Условия проверки
- Запущены Messenger.Web, Messenger.API и необходимые зависимости.
- Пользователь может войти через настроенный OIDC.
- DevTools открыты до начала сценария, включены Preserve log и отображение предупреждений/ошибок.
- Первичный прогон выполняется в чистом профиле без сторонних расширений.

## Сценарии

| Область | Действия | Ожидаемый результат |
|---|---|---|
| Главная и вход | Открыть главную, перейти на вход, начать SSO | Страницы загружаются без JS-ошибок; redirect URI корректен |
| Сессия | Войти, обновить страницу, выйти | Сессия сохраняется; после logout защищённые страницы недоступны |
| Список чатов | Открыть список, выполнить поиск, переключить папки | Список и счётчики обновляются, пустые состояния отображаются |
| Личный чат | Открыть чат, отправить и получить сообщение | Сообщения отображаются один раз и в правильном порядке |
| Групповой чат | Создать чат, добавить/удалить участника, изменить название | UI синхронизируется у участников |
| Сообщения | Ответить, переслать, отредактировать, удалить, закрепить, поставить реакцию | Каждая операция отражается в UI и после перезагрузки |
| Вложения | Загрузить, открыть и скачать разрешённый файл | Ошибки валидации показываются пользователю; файл доступен только участникам чата |
| Поиск и экспорт | Искать сообщения/пользователей, экспортировать чат | Результаты корректны; экспорт скачивается в выбранном формате |
| Отложенные сообщения | Создать, изменить и отменить отправку | Состояние синхронизируется после обновления страницы |
| Настройки | Изменить профиль, внешний вид, папки, приватность и уведомления | Настройки сохраняются и восстанавливаются после повторного входа |
| SignalR | Отключить сеть на короткое время и восстановить | Показывается состояние переподключения; подписки на чаты восстанавливаются |
| PWA | Проверить manifest, Service Worker, IndexedDB и offline-режим | SW активен; кэш и очередь работают без ошибок |
| Push | Разрешить уведомления и выполнить тестовую подписку | Подписка синхронизируется; при отказе разрешения UI остаётся работоспособным |

## Критерии чистой браузерной консоли

На успешном прогоне:
- нет Uncaught exceptions и unhandled promise rejections;
- нет ошибок загрузки собственных JS/CSS/изображений и SignalR transport;
- нет предупреждений, вызванных кодом приложения;
- нет вывода access token, refresh token, cookie, VAPID private key или других секретов;
- нет повторяющихся ошибок одного и того же запроса;
- ошибки браузерных расширений исключаются повторным прогоном в чистом профиле.

Ошибки ожидаемо отрицательных сценариев (например, неверный пароль или отказ пользователя в разрешении Push) должны быть представлены понятным состоянием/сообщением интерфейса, а не необработанным исключением.

## Network и серверная диагностика
- Успешные API-запросы возвращают ожидаемые статусы.
- 401/403 обрабатываются интерфейсом и не приводят к циклическим запросам.
- 4xx валидации показываются рядом с соответствующим действием.
- 5xx и сетевые ошибки приводят к безопасному сообщению и возможности повторить действие.
- SignalR WebSocket устанавливается и переподключается без циклического churn.
- В server logs нет необработанных исключений при успешных сценариях.

## Протокол результата

Для каждого сценария фиксируются: браузер и версия, дата, результат (Pass/Fail/Blocked), ошибка Console/Network, шаги воспроизведения и связанный issue/commit. Нельзя отмечать сценарий Pass только на основании успешной сборки или unit-тестов.
