# Entity Framework Core

## dotnet-ef

`dotnet-ef` — консольный инструмент Entity Framework Core CLI, предназначенный для создания и управления миграциями, обновления базы данных, генерации моделей из существующей БД и работы с `DbContext`.

## Установка Entity Framework Core CLI

### Глобальная установка

```bash
dotnet tool install --global dotnet-ef
```

### Обновление установленного инструмента

```bash
dotnet tool update --global dotnet-ef
```

### Проверка версии

```bash
dotnet ef --version
```

### Удаление глобального инструмента

```bash
dotnet tool uninstall --global dotnet-ef
```

# Миграции Entity Framework Core

## Создание миграции

```bash
dotnet ef migrations add <Имя_миграции> \
--project <Проект_с_DbContext> \
--startup-project <Startup_проект>
```

Пример:

```bash
dotnet ef migrations add InitialCreate \
--project Messenger.Infrastructure \
--startup-project Messenger.API
```

### Описание параметров

* `<Имя_миграции>` — название создаваемой миграции.
* `--project` — проект, содержащий `DbContext` и файлы миграций.
* `--startup-project` — проект, используемый для запуска приложения и получения конфигурации.

---

## Применение миграций к базе данных

```bash
dotnet ef database update \
--project <Проект_с_DbContext> \
--startup-project <Startup_проект>
```

Пример:

```bash
dotnet ef database update \
--project Messenger.Infrastructure \
--startup-project Messenger.API
```

Команда применяет к базе данных все миграции, которые ещё не были применены.

---

## Откат базы данных до конкретной миграции

```bash
dotnet ef database update <Имя_миграции> \
--project <Проект_с_DbContext> \
--startup-project <Startup_проект>
```

Пример:

```bash
dotnet ef database update InitialCreate \
--project Messenger.Infrastructure \
--startup-project Messenger.API
```

Для отката всех миграций:

```bash
dotnet ef database update 0 \
--project Messenger.Infrastructure \
--startup-project Messenger.API
```

---

## Удаление последней миграции

```bash
dotnet ef migrations remove \
--project <Проект_с_DbContext> \
--startup-project <Startup_проект>
```

Удаляет последнюю миграцию из проекта.

Перед удалением необходимо убедиться, что миграция не была применена к базе данных, либо сначала выполнить откат базы до предыдущей миграции.

---

## Просмотр списка миграций

```bash
dotnet ef migrations list \
--project <Проект_с_DbContext> \
--startup-project <Startup_проект>
```

Показывает список миграций и их состояние относительно базы данных.

---

## Генерация SQL-скрипта миграций

```bash
dotnet ef migrations script \
--project <Проект_с_DbContext> \
--startup-project <Startup_проект>
```

Для генерации SQL между двумя миграциями:

```bash
dotnet ef migrations script <От> <До> \
--project <Проект_с_DbContext> \
--startup-project <Startup_проект>
```

Пример:

```bash
dotnet ef migrations script InitialCreate AddUserProfile \
--project Messenger.Infrastructure \
--startup-project Messenger.API
```

# Работа с DbContext

## Просмотр доступных DbContext

```bash
dotnet ef dbcontext list \
--project <Проект_с_DbContext> \
--startup-project <Startup_проект>
```

Показывает все доступные классы `DbContext`.

---

## Просмотр информации о DbContext

```bash
dotnet ef dbcontext info \
--project <Проект_с_DbContext> \
--startup-project <Startup_проект>
```

Показывает информацию о найденном `DbContext` и его конфигурации.

---

## Генерация скомпилированной модели

```bash
dotnet ef dbcontext optimize \
--project <Проект_с_DbContext> \
--startup-project <Startup_проект>
```

Генерирует скомпилированную модель Entity Framework Core для ускорения работы с моделью.

# Scaffold — генерация моделей из PostgreSQL

## Команда

```bash
dotnet ef dbcontext scaffold "<Connection_String>" <Provider> \
--output-dir <Путь_к_папке_моделей> \
--context-dir <Путь_к_папке_контекста> \
--context <Имя_класса_контекста> \
--schema <Схема_БД> \
--data-annotations \
--project <Проект_для_выполнения_команды> \
--force \
--namespace <Пространство_имён_для_моделей> \
--context-namespace <Пространство_имён_для_контекста> \
--no-pluralize \
--use-database-names \
--tables <Имя_таблицы1> <Имя_таблицы2>
```

### Описание параметров

1. `<Connection_String>` — строка подключения к PostgreSQL:
   `"Host=<Host>;Port=<Port>;Database=<Database>;Username=<username>;Password=<Password>"`.
2. `<Provider>` — `Npgsql.EntityFrameworkCore.PostgreSQL`.
3. `--output-dir` — папка для классов моделей.
4. `--context-dir` — папка для `DbContext`.
5. `--context` — имя класса `DbContext`.
6. `--schema` — схема базы данных, например `public`.
7. `--data-annotations` — использовать Data Annotations.
8. `--project` — проект, в котором выполняется команда.
9. `--force` — перезаписывать существующие файлы.
10. `--namespace` — пространство имён моделей.
11. `--context-namespace` — пространство имён `DbContext`.
12. `--no-pluralize` — отключить автоматическое преобразование имён во множественное число.
13. `--use-database-names` — использовать оригинальные имена таблиц и колонок.
14. `--tables` — ограничить генерацию указанными таблицами.

# .NET Aspire

В проекте используется отдельный проект `Messenger.AppHost`, отвечающий за оркестрацию компонентов приложения.

В текущей конфигурации используются:

* PostgreSQL;
* RabbitMQ;
* Redis;
* `Messenger.API`;
* `Messenger.Web`;
* PgAdmin;
* RabbitMQ Management;
* RedisInsight.

Версия Aspire в проекте — `13.5.4`.

---


---

# Запуск приложения

Из корневой директории репозитория:

```bash
aspire run
```

Команда запускает `Messenger.AppHost`, который поднимает и связывает между собой ресурсы приложения.

---

# Запуск с Docker

```bash
aspire run -- --UseDocker true
```

При `UseDocker=true` Aspire создаёт инфраструктурные ресурсы в Docker:

* PostgreSQL;
* RabbitMQ;
* Redis.

Также доступны:

* PgAdmin;
* RabbitMQ Management;
* RedisInsight.

---

# Запуск без Docker

```bash
aspire run -- --UseDocker false
```

При `UseDocker=false` строки подключения к инфраструктурным сервисам берутся из конфигурации:

```text
DefaultConnection
RabbitMQ
Redis
```

Redis дополнительно проверяется и при необходимости запускается через WSL.

---

# Параметры AppHost

В `Messenger.AppHost` параметр `UseDocker` определяет способ запуска инфраструктуры:

```text
UseDocker=true
```

или:

```text
UseDocker=false
```

Параметр передаётся в AppHost следующим образом:

```bash
aspire run -- --UseDocker true
```

или:

```bash
aspire run -- --UseDocker false
```

# Публикация через Aspire

## Базовая команда

```bash
aspire publish -o <Папка_для_результатов>
```

* `-o` — каталог, в который Aspire помещает результаты публикации.
* `<Папка_для_результатов>` — путь к каталогу с результатами публикации.

Пример:

```bash
aspire publish -o ./out
```

---

## Публикация с Docker

```bash
aspire publish -o ./out-docker -- --UseDocker true
```

---

## Публикация без Docker

```bash
aspire publish -o ./out-nodocker -- --UseDocker false
```

---

## Шаблон команды `aspire publish`

```bash
aspire publish -o <Папка_для_результатов> -- <Параметры_AppHost>
```

Для текущего проекта:

```bash
aspire publish -o <Папка> -- --UseDocker <true|false>
```
